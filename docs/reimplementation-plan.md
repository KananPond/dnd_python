# 复刻计划：PLATO《dnd》(1975) 现代重制

> 目标不是 1:1 移植（原版 TUTOR 源码、PLATO 硬件时序、原始数值大多不可得），而是**机制骨架忠实 + 形式现代化**的可玩作品。
> 依据：`docs/research-dossier.md`（数据底稿与可信度分级）。
> 本文档 = **方案 + 进度**：第 1 节起描述**已交付的 Python 终端版**，第 7 节保留立项时的另两个待选项与最终拍板理由（决策留痕）。

## 0. 目标 / 非目标

**要做**
- 单屏字符地牢、俯视视角、局部视野、逐层下潜。
- 建角 → 属性/职业/等级/经验 → 战斗/法术/物品 → 宝物与进度 → 永久死亡 → 角色名册。
- 角色跨会话持久化（本地 JSON 存档）。
- 确定性内核：同一种子 + 同一输入序列 → 完全一致的重放（可测试、可回放、可压测）。
- 离线可跑、**零第三方依赖**（本机无外网，pip/npm 均不可达）。

**不做（本轮）**
- TUTOR 源码级复刻、PLATO 主帧时序/多用户同时在线、原版数值 1:1 复现、联网多人。
- 浏览器/图形前端、音效、i18n（见第 6 节路线图）。

## 1. 技术选型（已定稿）

| 层 | 选择 | 理由 |
|---|---|---|
| 语言 | **Python ≥ 3.10**（开发机 3.14），仅标准库 | 本机无 pip，任何框架都装不上；标准库 curses 已足够 |
| 交付形态 | **终端 TUI**：`curses`，`python3 -m dnd` 直接启动 | 最贴近单色字符终端的年代感，零安装、零构建 |
| 渲染 | curses 逻辑网格 + 256 色降级链（真彩 → 256 色 → 8 色） | 终端能力差异大，必须能逐级降级 |
| 视觉风格 | 黑底 + 琥珀/等离子橙辉光、记忆雾、光照层次；Unicode 框线（`─│┌┐`）＋ ASCII 兜底（`- \| +`） | PLATO 单色屏观感；中文终端常把框线当两格宽 |
| 内核 | 纯逻辑 + 可序列化状态 + 命令日志（`Game.commands`） | 可回放、可测试、可存档续玩 |
| 随机 | 自研 seeded PRNG（xoshiro256\*\* + splitmix64），内核内**禁用 `random` / `time`** | 确定性（`time` 仅存档/名册盖时间戳时用） |
| 测试 | `unittest`（标准库） | 零依赖；53 项用例 |
| 存档 | 本地 JSON（角色 + 地牢 + RNG 状态）、名人堂 `saves/roster.json` | 模拟原版"PLATO 用户记录"式持久化角色 |
| 开发辅助 | `tools/preview.py` 把界面渲染成 PNG（**唯一可选依赖 Pillow，游戏本体不需要**） | 改界面时"看一眼"观感，弥补终端难以截图的问题 |

## 2. 目录结构（实际）

```
DND/
├─ dnd/                  游戏包（python3 -m dnd）
│  ├─ rng.py             确定性 PRNG（xoshiro256**，状态可 JSON 序列化）
│  ├─ dice.py            掷骰表达式（'2d6+1' / 'd8' / '3'）
│  ├─ content.py         JSON 数据表加载与索引（按深度筛选怪物/物品）
│  ├─ data/*.json        职业 4 / 种族 4 / 怪物 12 / 物品 18 / 法术 5（均带 _meta 可信度）
│  ├─ level.py           地图生成（房间+走廊、门、楼梯、分层放置、BFS 连通性校验）
│  ├─ fov.py             视野（递归阴影投射，8 个八分圆）
│  ├─ entities.py        玩家 / 怪物 / 物品、建角、自动装备
│  ├─ game.py            内核状态机（回合、战斗、法术、物品、升级、胜负、状态哈希）
│  ├─ save.py            存档与名人堂名册
│  ├─ replay.py          确定性回放（seed + 命令序列 → 状态哈希）
│  ├─ ui/theme.py        配色与字形（调色板 + Unicode/ASCII 字形集 + 光照层次 + 降级）
│  ├─ ui/widgets.py      绘制辅助（框线/分隔线/进度条/按键提示；按显示宽度裁剪中文）
│  ├─ ui/describe.py     物品/法术说明（effect id → 玩家看得懂的一句话）
│  ├─ ui/tui.py          curses 主界面、建角界面、各类浮层、结局画面
│  └─ __main__.py        命令行入口
├─ tests/                test_core.py / test_tui.py / test_cli.py
├─ tools/                sim.py（机器人跑批）pty_smoke.py（伪终端冒烟）preview.py（渲染 PNG）
├─ docs/                 research-dossier.md（史料）reimplementation-plan.md（本文）how-to-play.md
├─ saves/                roster.json 与玩家存档（存档不入库，见 .gitignore）
└─ out/                  机器人跑批与预览输出（gitignore）
```

**模块依赖方向**（无环）：`dice → rng`；`entities/content → dice`；`level → entities`；`game → level/entities/replay 无关`；
`ui/* → game/level/entities`；`tools/*` 只依赖包内公开接口。`ui/theme.py` 在模块级 import curses，
因此 `__main__.py` 对 UI 一律**延迟导入**（保证 `--headless-demo`、`--list-saves` 在无 curses 环境也能跑）。

## 3. 保真度策略（"不 1:1"的落地办法）

三级标注，写进数据文件与文档：

- **L1 忠实层**：有据可查的骨架 —— 单屏字符地牢、俯视探索、逐层下潜、掷骰战斗、角色持久化、永久死亡、宝物驱动成长。
- **L2 现代化层**：键位与操作、帮助页、视野与记忆雾、怪物仇恨半径、生命自然恢复、上升式 AC、存档/名册、界面降级（ASCII/无颜色）。
- **L3 自由发挥层**：具体职业/种族/法术/怪物/数值/关卡布局/胜负条件（原版数据不可得，由我们定义）。

**数据出处登记**：每个内容条目所在文件附 `_meta: {"confidence": "documented|inferred|invented", "source": "<url|note>"}`；
界面提供「考据模式」开关（`P`）：开启后在侧栏显示当前所见内容的出处等级 —— 既诚实，也让"哪些是原版、哪些是我们的再创作"一目了然。
当前五张表全部为 `invented`（原版数值不可考），但**整体可在不改代码的前提下替换**。

**合规**：不使用 TSR/WotC 的商标与专有名词（不出现 D&D 品牌标识）；怪物/物品使用公有领域的通用奇幻词汇或自创名。

## 4. 复刻要素 → 实现方式（保真度矩阵）

| 原版要素（可信度） | 我们的做法 | 层级 | 落地位置 |
|---|---|---|---|
| 512×512 / 64×32 字符屏（A） | 逻辑地图 **48×26**，加标题栏/体征栏/日志/提示栏后正好装进 64×32 级别的终端；地图视口以玩家为中心滚动 | L1 | `level.py` `ui/tui.py` |
| 等离子橙单色辉光（A-） | 黑底 + 琥珀调色板（真彩/256/8 色三级降级）、地形远近明暗、`--no-color` | L1/L2 | `ui/theme.py` |
| TUTOR 教学语言（A） | 不还原语言；数据驱动（JSON）+ 纯函数内核实现同等逻辑 | L2 | `content.py` `dnd/data/` |
| PLATO 功能键（NEXT/HELP…）（A-） | 键盘单键命令 + 底部按键提示栏；`?` 帮助页（含考据说明） | L1/L2 | `ui/tui.py` |
| 局部视野的地牢探索（B） | 递归阴影投射 FOV（半径 9）+ 记忆雾（探索过但不可见 → 暗色） | L1 | `fov.py` `ui/tui.py` |
| 掷骰式战斗与职业差异（B） | d20 + 命中加值 vs 上升式 AC；20 暴击、1 必失手；职业命中成长表 | L1 结构 / L3 数值 | `game.py` `data/classes.json` |
| 法术（C） | 自定法术表（5 个：伤害/治疗/AC 增益/命中增益），数据文件可整体替换 | L3 | `data/spells.json` |
| 多层地牢（B/C） | 10 层、程序生成房间+走廊、门、深度控制怪物与宝物表、连通性校验（失败重生成） | L1 结构 / L3 数值 | `level.py` |
| 永久死亡（B） | 死亡即角色封存进名人堂（`roster.json`）并删档；`--modern` 提供一次"免死"（第二口气） | L1 + L2 选项 | `game.py` `save.py` |
| 角色持久化（B+） | 单槽 JSON 存档（含 RNG 状态）+ `--latest` 续玩 + `--list-saves` | L1/L2 | `save.py` |
| 目标/通关（C） | 第 10 层「深渊守卫」+「深渊遗物」：**取得遗物即胜利，不必杀死守卫**（守卫紧邻遗物但不压在其上） | L3 | `level.py` `game.py` |
| 玩家社群/排行榜（B+） | 本地名人堂名册（`R` 键 / `--roster`）；分享串未做 | L2 | `save.py` |

## 6. 测试与质量

- **确定性**：内核不触碰时钟/全局随机；`Game.state_hash()` 对 seed + 命令序列取哈希，`replay.run(seed, commands)` 在测试中断言一致；存档往返（`to_json`/`from_json`）后哈希不变。
- **单元/属性测试**：地图连通性（每层楼梯可达）、FOV 可见性、伤害与护甲边界、经验表单调性、种族/职业数值应用、存档往返、错档容错。
- **TUI 布局测试**：用假 curses 屏幕渲染，断言**布局关系**（谁压谁、是否越界、中文按显示宽度裁剪、Unicode/ASCII 字形切换、说明文案不回归）。
- **端到端**：`tools/pty_smoke.py` 在真实伪终端里启动 TUI，覆盖启动/渲染/移动/浮层/建角/F5 存档/`--latest` 续玩/退出。
- **机器人压测**：`tools/sim.py` 输出各职业平均深度、死亡原因分布、深度直方图，作为调参依据（尚未固化为回归阈值）。
- **可玩性检查表**：无鼠标可玩、帮助页覆盖全部命令、误操作可关（`Esc` 关浮层、`Q` 二次确认）、窄终端与无颜色可用。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 原版数值不可得（最大） | 复刻"不像原版" | 保真度分级 + 数据文件可替换 + 考据模式；将来拿到资料只改 JSON |
| 无外网/无依赖 | 不能用现成框架（textual/blessed 等） | 全自研零依赖栈：curses + unittest + 自研 PRNG |
| 终端能力差异 | 中文终端框线错位、无 256 色 | Unicode/ASCII 双字形集 + `--ascii`、三级配色降级、`--no-color` |
| 范围蔓延 | 交付遥遥无期 | M1–M2 已定义为"最小完整可玩版"，M3+ 为增强 |
| 终局硬拼劝退 | 玩家觉得不可能通关 | 守卫必生成但**遗物可抢走即胜**；隔离模拟成功率 18%~50%，README 明写"引开它再冲刺" |
| 商标与版权 | 法律风险 | 不用 D&D 品牌与专有名词；仅用公有领域通用词 |

## 8. 决策留痕（立项三选项 → 实际拍板）

立项时留了 D1–D3 三个待确认项，实际执行结果如下（**原方案为浏览器 Canvas 版，已废弃**）：

| 决策点 | 原选项 | 拍板结果 | 理由 |
|---|---|---|---|
| **D1 交付形态** | (a) 浏览器网页 Canvas 版（原推荐）｜(b) 终端 TUI｜(c) 两者共用内核 | **(b) Python 终端 TUI** | 本机无 pip/npm、无外网，(a) 的"零构建 ESM + Canvas"路线需要 Node 工具链与静态服务器；curses 是标准库，`python3 -m dnd` 即可跑，且年代感更贴 PLATO |
| **D2 复刻取向** | (a) 骨架忠实 + 现代化（推荐）｜(b) 更硬核原味 | **(a)** | 三级保真度标注已落地到 `dnd/data/*.json` 的 `_meta`/`confidence`；现代模式（`--modern`）作为可选项而非默认 |
| **D3 首版范围** | (a) 单人 + 本地存档 + 10 层（推荐）｜(b) 3 层原型｜(c) 追加分享榜/多人 | **(a)** | 已实现；分享串/多人仍在 M7 待办 |

**技术选型的偏离说明**（原计划的 Web 路线 vs 现状）：

| 项 | 原计划（JS Web 版） | 现状（Python TUI 版） |
|---|---|---|
| 语言/运行时 | 现代 ESM（`.mjs`）+ JSDoc，无构建 | Python 3.10+ 标准库 |
| 渲染 | Canvas 2D，512×512 逻辑分辨率 + 8×16 位图字模 | curses 字符网格，48×26 逻辑地图 + 终端原生字体 |
| 测试 | `node:test` | `unittest` |
| 静态服务器 | `node:http`（`tools/serve.mjs`，端口 8123） | 不需要：终端直接运行 |
| 存档 | localStorage/IndexedDB + 导入导出 | 本地 JSON 文件（`saves/`），导入导出 UI 待做 |
| 音频 | WebAudio 合成音效 | 未做（终端版无音频通道） |
| 目录 | `src/core` `src/content` `src/platform` `web/` | `dnd/`（`dnd/data` 承载 content 角色） |

> 已废弃方案原文（Canvas 512×512、字模表、`tools/serve.mjs` 等）仅存于本节对照表；实现层面**无一行 JS 残留**。
