# 复刻计划与技术说明：PLATO《dnd》(1975) 现代重制

> 目标不是 1:1 移植（原版 TUTOR 源码、PLATO 硬件时序、原始数值大多不可得），而是
> **机制骨架忠实 + 形式现代化**的可玩作品。依据：[`research-dossier.md`](research-dossier.md)（数据底稿与可信度分级）。
>
> 本文档 = **设计 + 实现 + 进度**：第 1 节起描述**已交付的 Python 终端版**；第 11 节保留立项时的备选项与最终拍板理由（决策留痕）。
> 所有数字与行为均按当前代码（`dnd/`、`tools/`、`tests/`）核对过，不是立项时的估计值。

## 0. 目标 / 非目标

**要做**

- 单屏字符地牢、俯视视角、局部视野、逐层下潜。
- 建角 → 属性/职业/等级/经验 → 战斗/法术/物品 → 宝物与进度 → 永久死亡 → 角色名册。
- 角色跨会话持久化（本地 JSON 存档）。
- 确定性内核：同一种子 + 同一输入序列 → 完全一致的重放（可测试、可回放、可压测）。
- 离线可跑、**零第三方依赖**（游戏本体只用 Python 标准库）。

**不做（本轮）**

- TUTOR 源码级复刻、PLATO 主帧时序/多用户同时在线、原版数值 1:1 复现、联网多人。
- 浏览器/图形前端、音效、i18n（见第 9 节路线图）。

## 1. 技术选型（已定稿）

| 层 | 选择 | 理由 |
|---|---|---|
| 语言 | **Python ≥ 3.10**（开发机实测 3.14.4），仅标准库 | 立项时本机无 pip/外网，任何框架都装不上；标准库 `curses` 已足够 |
| 交付形态 | **终端 TUI**：`python3 -m dnd` 直接启动 | 最贴近单色字符终端的年代感，零安装、零构建 |
| 渲染 | curses 字符网格 + 颜色三级降级（真彩 → 256 色 → 8 色） | 终端能力差异大，必须能逐级降级 |
| 视觉风格 | 黑底 + 琥珀/等离子橙辉光、记忆雾、光照层次；Unicode 框线 + ASCII 兜底 | PLATO 单色屏观感；中文终端常把框线当两格宽 |
| 内核 | 纯逻辑 + 可序列化状态 + 命令日志（`Game.commands`） | 可回放、可测试、可存档续玩 |
| 随机 | 自研 seeded PRNG（xoshiro256\*\* + splitmix64），内核内**禁用 `random` / `time`** | 确定性；`time` 只在存档/名册盖时间戳时用 |
| 测试 | `unittest`（标准库），123 项；另有 tmux 冒烟 44 项 | 零依赖；见第 8 节 |
| 存档 | 本地 JSON（角色 + 地牢 + RNG 状态）+ `_meta` 摘要、原子写；名人堂 `saves/roster.json` | 模拟原版"PLATO 用户记录"式持久化角色 |
| 开发辅助 | `tools/preview.py` 把界面渲染成 PNG，`tools/sim.py` 跑批，`tools/pty_smoke.py` 冒烟 | 终端的"看一眼"与自动化验证；Pillow 是**唯一可选依赖**，游戏本体不需要 |

**模块依赖方向**（无环）：

```
rng ← dice ← entities ← level ← game ← save
                 ↑         ↑       ↑      ↑
              content ─────┘       │      └── replay
                                   └── ui/*  ← __main__（延迟导入）
```

- `content.py` 只依赖标准库，是数据表的唯一入口（`load()` 带 `lru_cache`）。
- `game.py` 不依赖任何 UI；`ui/tui.py` 依赖 `ui/screens.py`，反向不成立。
- **`ui/theme.py` 在模块级 `import curses`**，因此 `__main__.py` 对 UI 一律延迟导入 ——
  这是为了让 `--headless-demo` / `--list-saves` / `--roster` 在没有 curses 的环境（Windows 原生 Python）也能跑。
  新增任何引用 UI 的代码都要照这个写法，否则这些无终端用法会直接崩。

## 3. 保真度策略（"不 1:1"的落地办法）

三级标注，写进数据文件与文档：

- **L1 忠实层**：有据可查的骨架 —— 单屏字符地牢、俯视探索、逐层下潜、掷骰战斗、角色持久化、永久死亡、宝物驱动成长。
- **L2 现代化层**：键位与操作、帮助页、视野与记忆雾、怪物仇恨半径、生命自然恢复、上升式 AC、存档/名册、界面降级（ASCII/无颜色）。
- **L3 自由发挥层**：具体职业/种族/法术/怪物/数值/关卡布局/胜负条件/世界观与背景故事（原版数据不可得，由本项目定义）。

**数据出处登记**：每个数据文件附
`_meta: {"confidence": "documented|inferred|invented", "source": "<url|note>", "license": "CC0-1.0"}`；
界面提供「考据模式」开关（`P`）：开启后在侧栏显示分级说明。当前六张表全部为 `invented`（原版数值不可考，
背景故事层更是纯粹的再创作），但**整体可在不改代码的前提下替换** —— `content.py` / `lore.py` 在运行期读 JSON，
没有任何硬编码内容。

**合规**：不使用 TSR/WotC 的商标与专有名词（不出现 D&D 品牌标识）；怪物/物品使用公有领域的通用奇幻词汇或自创名；
背景故事只借用"失落浮空帝国 / 维系魔法的源流 / 地下幽暗世界 / 疯法师地牢"这类**公共母题**，名词全部自造
（母题 → 改造对照见 `research-dossier.md` 第八节），并由 `tests/test_core.py::TestLore` 自动扫描守住。

## 5. 启动路径与主循环设计

**为什么是"一个脚本 + 一条命令"，而不是给每个平台写一份**

- `./pydnd.sh` 是唯一推荐入口，`python3 -m dnd` 是等价的底层入口（脚本只做前置校验，不碰游戏逻辑）。
- 用 **POSIX sh**（`#!/bin/sh`，只用 `test`/`case`/`printf`/`sed -n Np`），因为 macOS 的 `/bin/sh` 是 bash 3.2，
  自带 `readlink` 没有 `-f`、`dirname` 行为也略有差异 —— 不用任何 GNU 扩展，才能"mac 上没测过也大概率能跑"。
- **刻意不做 Windows 原生适配**：原生 Python 没有标准库 `curses`，要支持就得引入 `windows-curses`，
  与"零第三方依赖"的立项原则冲突。Windows 统一走 WSL2，脚本在原生 Windows（MINGW/MSYS/CYGWIN）下
  直接给出 `wsl --install` 指引并以退出码 2 结束。
- 校验顺序固定为：平台 → 解释器版本/`curses` → 是否真实终端 → 编码（必要时补 UTF-8 locale）→ 窗口尺寸 → 启动。
  每一个失败都对应一句明确的修法，而不是留一个 traceback。
- `--check` 走"只报告不启动"路径，且刻意不改动终端：正是跑不起来的时候才最需要它。
- `--headless-demo` / `--list-saves` / `--roster` 这三类不需要终端的用法会被脚本直接 `exec` 给 python，
  不干预 locale 与尺寸，因此也能在 CI、cron、ssh 非交互会话里用。

**两个必须守住的实现细节**（都踩过坑，已写进 `pydnd.sh` 注释）：

1. **脚本内不能用 here-document 喂 python**：`sh` 的 here-doc 从脚本自身的 stdin 读取，会把终端键盘输入吞掉，
   游戏就收不到按键了。所有内联 python 一律用 `-c '...'`。
2. **终端尺寸必须取 `/dev/tty`**：脚本用 `$( )` 捕获 python 输出时 fd 1 已被接到管道上，
   在 fd 1 上取尺寸必然 `ENOTTY`（只能拿到假的 80×24，尺寸提示就完全不可信）。

**主循环**（`dnd/__main__.py`）

```
开始页 ──新的冒险──→ 建角 ──→ 序章 ──→ 地牢 ──Esc 菜单──→ 存档管理
  │                                    ↑                  │
  ├──读取存档──→ 存档管理 ──────────────┘←────读取─────────┘
  ├──名人堂──→ 名册浮层
  └──退出游戏
```

- 开始页、建角、序章、存档管理、游戏内界面共用**同一个 curses 会话**（自写 `session` 类而不是 `curses.wrapper`）：
  每段各自 wrapper 会反复 `initscr/endwin`，观感上就是进出一次闪一下。
- 命令行捷径：`--load`/`--latest` 直接续玩；`--name/--class/--race` 三者齐备直接开局（**仍过一次序章**，
  `--no-prologue` 可跳过）；只给一部分则跳过开始页直接进建角并**预填**已给的项
  （没给的项绝不静默填默认值 —— 那正是"种族被钉成人类"的旧 bug）；
  `--seed` 单独出现仍会先过开始页（种子在真正开局时才用得上）；`--menu` 强制先回开始页；`--lore` 只打印背景故事。

## 6. 内核设计

**确定性**

- `game.py` 不 import `random` / `time`；所有随机走 `RNG`（xoshiro256\*\*），其状态可 JSON 序列化并随存档保存。
- `Game.state_hash()` 对种子 + 深度 + 回合 + 玩家 + RNG + 当前层取 SHA-256，用于回放断言。
- 每条改变状态的命令都会记进 `Game.commands`（含 `--debug` 的 `x`/`t`）；只有"什么都没发生"的失败命令会被弹回，
  以免回放对不上。畸形命令（脏存档、回放输入）只报错、不抛异常、不消耗回合。

**回合流程**（`Game._end_turn`）

```
玩家行动 → 刷新 FOV → 怪物行动（视野内或已警觉：相邻则攻击，仇恨半径内则靠近，否则游荡）
        → 若仍存活：增益倒计时 → 回合 +1 → 每 12 回合自然回 1 HP → 再刷新 FOV
```

**战斗**

- 玩家命中 = 职业成长（`attack_progressions`）+ 力量调整 + 增益；牧师对不死生物额外 +2。
- 怪物命中 = `attack_bonus`；双方都是 `d20 + 加值 ≥ AC`，20 暴击双倍、1 必失手。
- 伤害表达式统一走 `dice.py`（`'1d8'` / `'3d8+3'` / 纯数字）。

**几个容易踩的边界**（都有回归测试）

- 楼梯格可能被怪物占着：落点前先把挡路怪挤到相邻空格，否则玩家与怪物同格、怪物白打你而你打不到它。
- 读档后装备必须指回背包里的**同一个对象**，否则"已装备"标记会凭空消失。
- 地图生成必须保证关键目标（下楼梯 / 遗物）可达，且**所有可行走格都与起点连通**，否则重生成。

## 7. 界面设计

**布局常量**：地图 48×26；主界面最小 62×18（再小只显示"终端窗口太小"）；
宽度 ≥ 100 显示 26 格侧栏；日志固定 5 行；标题栏 2 行 + 底部（分隔线 + 日志 + 提示栏）。

**三条界面铁律**（写在 `ui/screens.py` 头部，全项目遵守）

1. 所有文本走 `widgets.put`（按**显示宽度**裁剪）：中文占两格，按字符数裁剪会越界（curses 报错或被终端折行）。
2. 选项行整行反白时文字左右各留一格 —— 宽度算错就会顶掉面板右边框。
3. 任何一屏都要能只用 ↑↓ + 回车走完，方向键在每一屏都是"移动光标"。

**几个"只算一次"的收敛点**

- `screens.panel_rect(h, w, ...)`：不落笔地算面板尺寸，`draw_panel` 与调用方（如游戏内确认框要跟暂停菜单对齐）共用，
  避免公式复制出错。`h` 与 `w` 都是必须参数 —— 曾经只收高度，导致 24 行窗口里所有面板被压到 22 格宽。
- `theme.PALETTE` 是配色的唯一事实来源（语义名 → RGB），256 色/8 色索引在 `init_colors()` 里按色彩距离推导；
  同一份 RGB 也被 `tools/preview.py` 用来渲染 PNG。
- `theme.configure_glyphs()`：UTF-8 终端用 Unicode 框线，`--ascii` / `DND_ASCII=1` / 非 UTF-8 终端退回 ASCII；
  显式指定的字形集会被"钉住"，不会被后续的 `init_colors()` 探测改回去。
- `theme.attr()` 在 `--no-color` 下用属性位（`A_REVERSE`/`A_DIM`）模拟反白与变暗，保住层次感。
- 浮层只在**游玩区**里居中（不跨到侧栏上）；先把面板内部刷成空格再画内容，避免地图字形透出来；
  页脚写在**下边框**上而不是压在最后一行内容上。

**游戏内浮层**：背包（按字母使用/装备）、法术（按字母施放，MP 不足的标灰）、帮助、名人堂、
传送（仅 `--debug`）、暂停菜单（继续/保存进度/存档管理/返回开始页/退出）、结算（胜利/阵亡 + 种子）。

## 11. 决策留痕

立项时留了 D1–D3 三个待确认项，实际执行结果如下（**原方案为浏览器 Canvas 版，已废弃**）：

| 决策点 | 原选项 | 拍板结果 | 理由 |

## 12. 已知技术债（明确记录，尚未清理）

- `dnd/ui/tui.py` 里 `roster_screen` **定义了两次**（后一个覆盖前一个，行为一致但冗余），应在下次改这里时删掉一份。

- 存档目录固定为仓库内 `saves/`，没有 `DND_SAVE_DIR` 之类的覆盖手段（对 `pipx install` 的用户不友好）。
